# RAG 知识库问答系统 — 架构设计

## 一、什么是 RAG？

### 核心概念

RAG（Retrieval-Augmented Generation，检索增强生成）是一种**将信息检索与文本生成相结合**的技术架构。

```
用户提问
    │
    ▼
┌─────────────────────────────────────────────────────┐
│                     RAG 系统                          │
│                                                      │
│  ┌──────────┐    ┌──────────┐    ┌──────────┐       │
│  │  检索    │───→│  增强    │───→│  生成    │       │
│  │ Retrieve │    │ Augment  │    │ Generate │       │
│  └──────────┘    └──────────┘    └──────────┘       │
│       │               │               │              │
│    从知识库         将检索结果        LLM 基于       │
│    找到相关         + 用户问题       "知识+问题"    │
│    文档片段         组装成提示词     生成回答        │
└─────────────────────────────────────────────────────┘
    │
    ▼
  AI 回答（带引用来源）
```

### 为什么 LLM 本身不够？

| 问题 | 说明 | RAG 如何解决 |
|------|------|-------------|
| **知识截止** | LLM 训练数据有截止日期，不知道最新信息 | 实时从知识库检索最新文档 |
| **幻觉** | LLM 可能编造事实 | 回答基于检索到的实际文档内容 |
| **领域知识** | 通用 LLM 不了解企业私有知识 | 只从企业文档库中检索 |
| **可解释性** | 不知道 LLM 为什么这么回答 | 可以追溯到具体文档片段 |

### 业务场景示例

```
你是一家律所的 CTO，律师们每天需要查询：
"2024年《公司法》修订后，注册资本认缴期限有什么变化？"

❌ 纯 LLM 方案：
   可能用到过时的法律条文，或者编造不存在的条款

✅ RAG 方案：
   1. 检索 → 从法律知识库中找到《公司法》2024修订版相关章节
   2. 增强 → 将法律条文原文 + 用户问题组装成 prompt
   3. 生成 → LLM 基于真实法条给出准确回答 + 引用来源
```

## 二、为什么需要 Chunk（文档切片）？

### 核心原因

LLM 的上下文窗口是**有限的**。一份 PDF 可能有 100 页（~50000 tokens），而一次 API 调用能处理的文本量是有限的（即使是 128k 窗口，全部塞进去也浪费 Token + 检索不精确）。

### Chunk 的策略

```
整份文档 (50000 tokens)
├── Chunk 1 (500 tokens)  "2024年公司法修订案第一章..."
├── Chunk 2 (500 tokens)  "第二章 公司登记..."
├── Chunk 3 (500 tokens)  "第三章 注册资本..."
├── ...
└── Chunk N (500 tokens)  "第十章 附则"

用户问："注册资本认缴期限？"
→ 检索到 Chunk 3（最相关）
→ 只发送 Chunk 3 + 用户问题给 LLM
→ Token 消耗少，回答精准
```

### Chunk 的关键参数

| 参数 | 作用 | 经验值 |
|------|------|--------|
| **chunk_size** | 每个切片的 Token 数 | 500-1000（中文可小一些） |
| **chunk_overlap** | 相邻切片的重叠 Token 数 | 100-200（防止上下文被切断） |
| **separators** | 分隔符优先级 | ["\n\n", "\n", "。", "！", "？", "，", " "] |

### 为什么需要 overlap？

```
文档："注册资本认缴期限为五年。\n\n股东应当在..."

错误切法：
  Chunk 1: "注册资本认缴期限为五年。"
  Chunk 2: "股东应当在..."  ← 上下文丢失

正确切法（overlap=50）：
  Chunk 1: "注册资本认缴期限为五年。"
  Chunk 2: "五年。\n\n股东应当在..."  ← 保留了"五年"
```

## 三、为什么需要 Embedding？

### 核心概念

Embedding 是将**文本转换为向量（数字数组）**的过程。

```
"注册资本认缴期限"  ─→  [0.12, -0.45, 0.87, ..., 0.33]  (1536维向量)
"注册资金缴纳时间"  ─→  [0.15, -0.42, 0.85, ..., 0.30]  (语义相近，向量也相近)

语义相近 → 向量距离小（余弦相似度高）
语义不同 → 向量距离大
```

### Embedding 解决了什么问题？

传统关键词搜索（如 Elasticsearch）只能做**字面匹配**：

```
用户搜："注册资本认缴期限"

❌ Elasticsearch 匹配："资本"、"认缴"、"期限"
   → "资本利得税"（误匹配，因为都有"资本"）
   → "缴纳社保的期限"（误匹配，因为都有"缴纳"+"期限"）

✅ Embedding 语义搜索：
   → "2024年公司法修订：注册资本认缴期限为五年" ✓（语义最相关）
   → "2024年股东出资时间规定" ✓（语义相近，字面不同）
```

### 常见的 Embedding 模型

| 模型 | 维度 | 适用场景 | 特点 |
|------|------|---------|------|
| `text-embedding-3-small` | 1536 | 通用场景 | OpenAI，质量高，费用低 |
| `text-embedding-3-large` | 3072 | 高精度场景 | OpenAI，精度最高 |
| `BAAI/bge-base-zh-v1.5` | 768 | 中文场景 | 开源免费，中文优秀 |
| `BAAI/bge-large-zh-v1.5` | 1024 | 中文高精度 | 开源免费，中文最好之一 |

## 四、为什么需要向量数据库？

### 核心问题

Embedding 之后，我们有了很多向量，但是：

1. **存哪里？** 每个 Chunk 对应一个 1536 维向量，10000 个 Chunk = 1536 万维数据
2. **怎么搜？** 用户提问时，也要转为向量，然后找到"最相似"的 K 个 Chunk
3. **要多快？** 应该能在毫秒级别返回结果

### 普通数据库 vs 向量数据库

```
普通数据库 (PostgreSQL/MySQL):
  SELECT * FROM documents WHERE content LIKE '%认缴%'
  → 只能做关键词匹配
  → 速度：线性扫描全表 O(n)

向量数据库 (Chroma/Pinecone/Weaviate):
  SELECT * FROM documents 
  ORDER BY embedding <=> query_embedding  — 余弦距离
  LIMIT 5
  → 可以语义搜索
  → 速度：ANN 索引 O(log n)
```

### 常见向量数据库对比

| 方案 | 类型 | 适用场景 | 优点 | 缺点 |
|------|------|---------|------|------|
| **Chroma** | 本地嵌入式 | ✅ 本项目 | 零配置、Python/JS 支持、轻量 | 单机、不适合大规模 |
| Pinecone | 云服务 | 生产环境 | 高可用、自动扩缩 | 付费、需联网 |
| Weaviate | 自托管 | 中等规模 | 混合搜索、开源 | 需 Docker |
| Qdrant | 自托管 | 高并发 | 性能好、Rust 实现 | 需 Docker |
| pgvector | PostgreSQL 插件 | 已有 PG | 不需额外数据库 | 性能中等 |

### 本项目选择 Chroma 的原因

- **零配置**：`npm install chromadb` 即可使用，不需要 Docker
- **客户端模式**：在 Next.js API Route 中直接运行，不需要独立服务
- **LangChain 原生支持**：`@langchain/chroma` 一行代码集成
- **持久化**：可以保存到本地磁盘文件
- **适合教学**：架构简单，容易理解 RAG 全流程

## 五、完整 RAG 数据流

```
┌─────────────────────────────────────────────────────────────────┐
│                         RAG 完整流程                               │
├─────────────────────────────────────────────────────────────────┤
│                                                                   │
│  ========== 索引阶段 (Indexing) ==========                       │
│                                                                   │
│  PDF文档                                                         │
│    │                                                             │
│    ▼                                                             │
│  文档加载 (PDFLoader)                                            │
│    │                                                             │
│    ▼                                                             │
│  文档切片 (RecursiveCharacterTextSplitter)                       │
│    │                                                             │
│    ├── Chunk 1: "2024年公司法修订案第一章..."                    │
│    ├── Chunk 2: "第二章 公司登记..."                             │
│    ├── Chunk 3: "第三章 注册资本..."                             │
│    └── ...                                                       │
│    │                                                             │
│    ▼                                                             │
│  Embedding (text-embedding-3-small / BGE)                        │
│    │                                                             │
│    ├── Chunk 1 → [0.12, -0.45, ..., 0.33] (向量)                │
│    ├── Chunk 2 → [0.08, -0.32, ..., 0.41]                       │
│    └── ...                                                       │
│    │                                                             │
│    ▼                                                             │
│  向量存储 (Chroma)                                               │
│    │  Document 1: { text: "...", metadata: { source: "..." } }  │
│    │  + Vector:  [0.12, -0.45, ..., 0.33]                       │
│    └── ...                                                       │
│                                                                   │
│  ========== 查询阶段 (Retrieval) ==========                      │
│                                                                   │
│  用户提问: "注册资本认缴期限有什么变化？"                        │
│    │                                                             │
│    ▼                                                             │
│  Query Embedding (同一模型将问题转向量)                          │
│    │                                                             │
│    │  [0.15, -0.38, ..., 0.28]                                   │
│    ▼                                                             │
│  向量检索 (Chroma.similaritySearch)                              │
│    │                                                             │
│    │  Top 3 结果:                                               │
│    │  1. Chunk 15: "注册资本认缴期限为五年" (相似度 0.92)       │
│    │  2. Chunk 18: "股东出资时间规定" (相似度 0.87)             │
│    │  3. Chunk 3:  "公司章程载明事项" (相似度 0.76)             │
│    ▼                                                             │
│  Prompt 组装                                                     │
│    │                                                             │
│    │  你是一个法律顾问。请基于以下文档内容回答问题。             │
│    │  如果文档中没有相关信息，请如实说不知道。                  │
│    │                                                             │
│    │  文档内容：                                                 │
│    │  [Chunk 15 原文]                                            │
│    │  [Chunk 18 原文]                                            │
│    │                                                             │
│    │  问题：注册资本认缴期限有什么变化？                        │
│    ▼                                                             │
│  LLM 生成 (DeepSeek / GPT)                                       │
│    │                                                             │
│    ▼                                                             │
│  AI 回答（带引用）                                               │
│    "根据2024年公司法修订，有限责任公司的注册资本认缴期限        │
│     最长不超过五年。相比之前的无期限认缴制，新法明确了          │
│     认缴期限，加强了对股东出资的约束。[来源: 2024公司法.pdf]"  │
│                                                                   │
└─────────────────────────────────────────────────────────────────┘
```

```
src/
├── app/
│   └── rag/                           # RAG 知识库页面

│   ├── document-upload.tsx            # PDF 上传组件
│   ├── document-list.tsx              # 文档列表/管理
│   ├── rag-chat.tsx                   # RAG 聊天界面
│   └── source-badge.tsx               # 来源引用标签
│
├── lib/rag/                           # RAG 核心逻辑
│   ├── document-loader.ts             # 文档加载器 (PDF)
│   ├── text-splitter.ts              # 文本切片器
│   ├── embeddings.ts                 # Embedding 服务选择
│   ├── vector-store.ts               # Chroma 向量存储
│   └── rag-chain.ts                  # RAG 问答链
│
├── app/api/rag/
│   ├── upload/route.ts               # POST: 上传 PDF → 索引
│   ├── documents/route.ts            # GET: 文档列表 / DELETE: 删除
│   └── query/route.ts                # POST: 提问 → 检索 → 回答
│
└── types/
    └── rag.ts                        # RAG 类型定义
```

### 组件层级

```
<RAGPage>
  ├── <Navbar />                       ← 已有的导航栏
  ├── <DocumentUpload />               PDF 上传（拖拽 + 点击）
  ├── <DocumentList />                 已索引文档列表
  │   └── <DocumentItem /> (×N)       单个文档状态
  └── <RAGChat />                      RAG 问答界面
      ├── <ChatMessages />             ← 复用消息列表
      │   └── <ChatMessage>
      │       └── <SourceBadge />      来源引用
      └── <ChatInput />               ← 复用输入框
```

### API 结构

| 路由 | 方法 | 说明 |
|------|------|------|
| `/api/rag/upload` | POST | 上传 PDF → 切片 → Embedding → 存入 Chroma |
| `/api/rag/upload` | GET | 获取已上传文档列表 |
| `/api/rag/upload` | DELETE | 删除指定文档及其向量 |
| `/api/rag/query` | POST | 用户提问 → 检索 → Prompt 组装 → LLM 流式回答 |

## 八、关键问题

### Q1: 中文 RAG 和英文 RAG 有什么区别？
- 中文 Token 数更多（一个中文词 ≈ 2 tokens）
- Chunk size 建议更小（300-500 而不是 1000）
- 推荐中文 embedding 模型（BGE-base-zh）
- 分隔符优先级：`["\n\n", "\n", "。", "！", "？"， "，"]`

### Q2: 如何评估 RAG 效果？
| 指标 | 说明 | 测量方式 |
|------|------|---------|
| Retrieval Precision | 检索结果是否都相关 | 人工标注 Top-K 准确性 |
| Answer Correctness | 回答是否准确 | 与标准答案对比 |
| Citation Accuracy | 引用是否真实 | 检查 LLM 是否"编造"引用 |
| Latency | 响应时间 | 端到端延迟 |

### Q3: 生产环境优化方向
| 优化 | 方案 |
|------|------|
| 检索质量 | Hybrid Search（向量 + 关键词）+ Reranker |
| 性能 | Embedding 缓存、向量索引优化、异步预处理 |
| 大规模 | 从 Chroma 迁移到 Pinecone/Qdrant |
| 多租户 | 向量中添加 tenant_id 元数据字段隔离 |
| 文档更新 | 增量索引 + 版本管理 |
