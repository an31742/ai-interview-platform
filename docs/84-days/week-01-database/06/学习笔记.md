# Day 6 学习笔记 — SSE 聊天接入数据库

日期：2026-08-21
学习主题：面试 SSE 对话过程每轮都存到数据库

---

## 一、目标

把 `POST /api/interview/chat` 接上数据库。

**每轮聊天的流程现在是：**
```
前端说一句 → chat/route.ts 调 LangGraph → 返回 AI 回复（SSE）
                                              ↘
                                                不存数据库 ❌
```

**目标流程：**
```
前端说一句 → chat/route.ts 调 LangGraph → 返回 AI 回复（SSE）
           ↘                             ↘
             存一条 user 消息到数据库 ✅   存一条 ai 消息到数据库 ✅
```

---

## 二、chat/route.ts 改造点（今天的重头戏）

### 当前的 chat/route.ts（只做了 SSE 输出，不存库）

位置：`src/app/api/interview/chat/route.ts`

```
步骤：
  1. 解析 body（messages, phase, resumeContext, sessionId 等）
  2. RAG 检索简历上下文（如果有 resumeId）
  3. 调 LangGraph processInterviewTurn() 拿到 AI 回复
  4. 构建 SSE 流，逐字输出（打字机效果）
  5. 输出 evaluation（评分）、phase-change（阶段变更）、done（结束）
```

**缺的就是数据库存库步骤！**

### 改造思路（接三层架构）

```
改造后：
  1. 解析 body  → 多拿一个 sessionId（必须！不然存哪场面试里？）
  2. Token 验证 → 拿到 userId（不然谁知道这条消息是谁的？）
  3. 存 user 的消息：
     → interviewService.appendMessage(sessionId, userId, {
         role: "user", content: "...", type: "answer", phase, score, evaluation
       })
  4. 调 LangGraph 拿 AI 回复  ←  这步和之前一样
  5. SSE 输出 AI 回复 + 评分   ←  这步也和之前一样
  6. SSE 流关闭后，存 ai 的消息：
     → interviewService.appendMessage(sessionId, userId, {
         role: "ai", content: aiText, type: "question", phase, score, evaluation
       })
```

## 三、前端也要配合改（sessionId 贯穿全程）

### 当前面试开始的流程（没 sessionId）

```
前端点「开始面试」：
  1. Zustand store.createSession() → 生成一个随机 id 存 localStorage
  2. 所有消息加进 store.sessions[id].messages
  3. 调 POST /api/interview/chat（body 里不带 sessionId）
```

### 改造后（必须先调 API 拿 sessionId）

```
前端点「开始面试」：
  1. 调 POST /api/interview/start（body: { resumeId, mode, difficulty, jdContent }）
  2. API 返回 { session: { id: "clx...", ... } }  ←  这个 id 是数据库的 cuid！
  3. store.currentSessionId = session.id
  4. 每轮聊天调 POST /api/interview/chat 时 body 带 sessionId: session.id
  5. 结束时调 PATCH /api/interview/:id → status=completed
```

## 四、改完后怎么验证？（一步步测）

### ① 先测 API（用 curl 或 Postman）

```
Step 1 — 创建面试：
  curl -X POST http://localhost:3000/api/interview/start \
    -H "Cookie: token=你的JWT" \
    -H "Content-Type: application/json" \
    -d '{"mode":"tech","difficulty":"mid","resumeId":1}'
  
  → 应该返回 sessionId（类似 "clxabc123..."），记下它

Step 2 — 查数据库（用 DB Browser 看 dev.db）：
  打开 InterviewSession 表 → 应该多了一行记录 ✅

Step 3 — 发一轮对话（存消息）：
  curl -X POST http://localhost:3000/api/interview/chat \
    -H "Cookie: token=你的JWT" \
    -H "Content-Type: application/json" \
    -d '{
      "sessionId":"刚才记下的id",
      "messages":[{"role":"user","content":"我叫小明","type":"answer"}],
      "phase":"self-intro"
    }'

Step 4 — 再查数据库：
  Message 表 → 应该多了 2 条！（一条 user 的，一条 ai 的）✅
```

### ② 用浏览器跑完整流程

```
1. 登录
2. 上传一份简历
3. 点「开始面试」→ 浏览器 Network 里看到 POST start 返回 session.id
4. 聊 3-5 轮
5. 点「结束面试」→ Network 里看到 PATCH /interview/:id 返回 success:true
6. 刷新浏览器 → 进「我的面试」页面 → 看到刚才的面试记录 ✅
7. 点进去详情 → 看到 3-5 轮对话全部都在 ✅（不是从 localStorage，是从 API 拉的！）
```

## 六、关键知识点（学习目标）

1. **SSE + 数据库怎么结合？** — SSE 是流式输出给用户看，但数据是「先存库再输出」还是「输出完再存库」？两种都可以，我们选「用户消息先存，AI 消息输出完再存」
2. **sessionId 的意义** — 所有消息必须带一个「归属标志」：属于哪场面试？没有 sessionId 的消息是野数据！
3. **Token 验证在 SSE 接口也要做** — chat 接口之前居然没验 Token！任何人都能调这个接口调 AI 浪费钱！今天必须补上！
4. **Zustand persist 不再是数据源** — 改完后 localStorage 只是「缓存」，真数据源是 API（数据库）
