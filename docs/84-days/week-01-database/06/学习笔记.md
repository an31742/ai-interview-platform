```
⑦ controller.close() 之后，存 ai 消息（记第二笔账）：appendMessage(role="ai")
```

## 三、今天学到的核心知识点

### 1. 为什么 SSE 接口也要做 Token 验证？

改造前 chat/route.ts **完全没有验 Token**！任何人都能直接调这个接口，无限调用 AI，烧你的额度。

现在加了：`extractTokenFromCookie || extractTokenFromHeader → verifyToken → payload.sub`，和别的 Controller 完全一致。

### 2. 为什么 sessionId 必填？

消息必须有「归属标志」——属于哪场面试。没有 sessionId 的消息是野数据，不知道存哪。

### 3. Service 方法内部自己做了权限校验，Controller 不用重复判空

`getInterviewById` 内部逻辑：
```ts
const session = await repo.findSessionById(sessionId);
if (!session) throw new BusinessError("面试不存在");
if (session.userId !== userId) throw new BusinessError("无权操作此面试");
return session;
```

**关键理解：** 它用 `throw` 来传达错误，所以 Controller 层拿到返回值就一定成功，不需要 `if (!session)` 判空。10 个 Controller 调它，都不用重复写判空。

### 4. ⚠️ 踩坑：BusinessError 只接受 1 个参数！

```ts
// ❌ 错误写法（编译报错："应有 1 个参数，但获得 2 个"）
throw new BusinessError("面试已结束", 400);

// ✅ 正确写法
throw new BusinessError("面试已结束");
```

原因：`BusinessError` 的构造函数是 `constructor(message: string)`，只有一个 `message` 参数，没有 status 参数。状态码是在 Controller 的 catch 里统一定的（BusinessError → 400，其他 → 500）。

### 5. ⚠️ 踩坑：最外层 catch 必须区分 BusinessError

改造前 catch 把所有错误都当 500：
```ts
} catch (err) {
  return errorResponse(err.message, 500);  // ❌ 连 BusinessError 都变 500
}
```

改造后：
```ts
} catch (err) {
  if (err instanceof BusinessError) {
    return errorResponse(err.message, 400);  // 业务错误 → 400
  }
  return errorResponse(err.message, 500);    // 系统错误 → 500
}
```

### 6. appendMessage 内部已经判断「面试已结束」

`appendMessage` 内部第 110-113 行已经有：
```ts
if (session.status === "completed") {
  throw new BusinessError("面试已结束，无法追加消息");
}
```

所以 Controller 层不用重复判断。而且存 user 消息发生在调 AI **之前**，第一次 appendMessage 就会拦住「已结束」的面试，不会浪费 AI 钱。

### 7. TextEncoder（发数据）vs TextDecoder（收数据）

| 工具 | 方向 | 干嘛 | 餐厅比喻 |
|------|------|------|---------|
| TextEncoder | 服务器 → 浏览器 | 字符串编码成字节数组 | 把菜装盘端出去 |
| TextDecoder | 浏览器 → 服务器 | 字节数组解码成字符串 | 把菜倒进碗里吃 |

我们是服务器发 SSE 数据出去，所以用 `new TextEncoder()` + `encoder.encode(...)`。

### 8. 存 ai 消息的位置：必须放在 ReadableStream 的 start 函数内、controller.close() 之后

三个位置对比：
- ❌ 放 ReadableStream **外面**（return Response 之后）→ return 之后代码不执行！
- ❌ 放 controller.close() **之前** → 用户还没看完回复，先存库会增加延迟
- ✅ 放 controller.close() **之后**、catch 之前 → SSE 已完整输出，用户已看完，再默默存库，不影响体验

关键：`new ReadableStream({ async start(controller) {...} })` 只是**创建**流对象，start 里带 `await` 的内容是 Next.js 真正发数据时才执行的。
