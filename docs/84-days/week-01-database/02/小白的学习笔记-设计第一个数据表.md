## 一、我今天最大的三个领悟

### 领悟 1：Prisma 是什么

```
我以前以为：  Prisma = 数据库
现在理解了：  Prisma = 数据库的"中介/翻译官"

Prisma Schema  = 我用 Prisma 的语法描述"数据长什么样"
Prisma 自己   = 把我的描述翻译成 SQL 语句发给数据库
数据库        = 真正存数据的地方（SQLite / PostgreSQL）

就像：
  我用中文说"给我查一下邮箱是 a@b.com 的用户"
  Prisma 翻译成 SQL：SELECT * FROM users WHERE email = 'a@b.com'
  发给数据库执行
```

### 领悟 2：设计表 = 回答 3 个问题

设计一个字段就是问自己：

```
① 这个信息有没有？（必须有 → 不加 ? / 可能没有 → 加 ?）
② 这个信息能重复吗？（不能 → @unique）
③ 这个信息谁生成？（系统自动 → @default(now()) / 用户填 → 不写 @default）
```

### 领悟 3：前端 vs 后端

```
前端 = 负责"怎么展示"和"用户怎么操作"
后端 = 负责"数据存在哪"和"数据长什么样"
数据库 = 真正躺在那里的"硬盘"

后端通过 Prisma 和数据库聊天
前端通过 API 和后端聊天
```

## 二、Prisma Schema 语法速查表（我目前学到的）

```
model 表名 {
  字段名  类型   修饰符
}

┌────────────┬────────────────────────────┬──────────────────────┐
│ 写法        │ 意思                        │ 例子                   │
├────────────┼────────────────────────────┼──────────────────────┤
│ String      │ 存文字，必填                 │ name String          │
│ String?     │ 存文字，可选（可以为空）       │ avatar String?       │
│ Int         │ 存整数                      │ age Int              │
│ DateTime    │ 存时间                      │ createdAt DateTime   │
│ Json        │ 存任意结构的数据              │ parsed Json?         │
│ @id         │ 这是主键（唯一标识）           │ id String @id        │
│ @default()  │ 自动生成默认值                │ @default(cuid())     │
│             │                            │ @default(now())      │
│ @unique     │ 值必须唯一，不能重复           │ email String @unique │
│ @updatedAt  │ 修改时自动更新时间             │ updatedAt DateTime   │
└────────────┴────────────────────────────┴──────────────────────┘
```

## 三、我现在的 Schema（User 表）

```prisma
model User {
  id             String   @id @default(cuid())
  email          String   @unique
  name           String
  passwordHash   String
  createdAt      DateTime @default(now())
  updatedAt      DateTime @updatedAt
}
```

**每个字段为什么这么写：**

| 字段 | 类型 | 修饰符 | 为什么？ |
|------|------|--------|---------|
| id | String | @id @default(cuid()) | 自动生成唯一标识，不用自增（怕暴露用户数、怕以后合并冲突） |
| email | String | @unique | 登录要用，两个人不能用同一个邮箱 |
| name | String | 无 | 用户名字，必须填，不用唯一（可以重名） |
| passwordHash | String | 无 | 存加密后的密码乱码，不是存原文 |
| createdAt | DateTime | @default(now()) | 创建时数据库自动记时间，不用代码管 |
| updatedAt | DateTime | @updatedAt | 修改时数据库自动更新，不用代码管 |

## 四、我学到的重要概念

### 哈希（Hashing）是什么

```
密码不存原文，存"加密后的乱码"：

注册时：
  用户输入 "abc123"
  → 用 bcrypt 库加密成 "$2b$10$rO0aKbF8..."（哈希值）
  → 存到数据库的 passwordHash 字段里

登录时：
  用户输入 "abc123"
  → 用 bcrypt 比对：输入的 "abc123" 和 数据库里的乱码是否匹配
  → 匹配 → 登录成功
```

**重要：哈希是在代码里写的，不是 Schema 里写的。**

### MySQL、PostgreSQL 和 SQLite 是什么关系

```
都是"数据库"（真正存数据的地方）
就像：可口可乐、百事可乐、非常可乐 都是可乐

SQLite     = 存在一个文件里，适合学习/小项目
PostgreSQL = 需要装服务器，适合正式项目
MySQL      = 另一种要装服务器的数据库
Prisma     = 不管底下用哪种，写法一样（改一行配置就换）
```

### Prisma Schema 换语言还能用吗？

```
Prisma 的写法（model User { ... }）只适用于 JS/TS 的 Prisma

但"设计的思路"所有语言都一样：
  Java  → 用 JPA，语法不同但要想的问题一样
  Go    → 用 GORM，语法不同但要想的问题一样
  Python → 用 SQLAlchemy，语法不同但要想的问题一样

学会 Prisma 的思路，换语言只是换本"词典"。
```
