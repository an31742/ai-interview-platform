## 三、Schema 修正记录（共 11+1 处错误）

| # | 位置 | 错误写法 | 正确写法 | 说明 |
|---|------|---------|---------|------|
| 1 | Resume.id | `String @default(autoincrement())` | `Int @default(autoincrement())` | 自增必须是整数类型 |
| 2 | 全篇 | `string` / `int` | `String` / `Int` | Prisma 类型首字母**永远大写** |
| 3 | InterviewSession.id | `default(cuid())` | `@default(cuid())` | 修饰符前缺 `@` |
| 4 | InterviewSession | `resumeId` 定义两次（第 49+55 行） | 删一个，保留 `Int?` | 字段不能重复 |
| 5 | InterviewSession | `messages string` | `messages Message[]` | 关联字段不是 string，是关系声明 |
| 6 | InterviewSession | `@relation(fuileds:...)` | `@relation(fields:...)` | 拼写错误 fields |
| 7 | InterviewSession.status | `@default('preparing')` 单引号 | `@default("preparing")` 双引号 | Prisma 字符串默认用双引号 |
| 8 | 模型名 | `messageSession` | `Message` | 模型名单数 PascalCase |
| 9 | Message.content | `content 对话的内容` | `content String` | 缺类型 |
| 10 | Message | 缺字段 evaluation, createdAt, session 关系 | 补上 | |
| 11 | InterviewSession | 缺 duration, score, createdAt, updatedAt, resume 关系 | 补上 | |
| 12 | User | 缺 `interviewSessions InterviewSession[]` | 补上 | 一对多关系两边都要声明！ |

## 四、两张新表的字段设计

### InterviewSession（一场面试）

```
id          String  @id @default(cuid())   // cuid，不暴露面试数量
userId      String                        // 哪个用户的面试（外键）
resumeId    Int?                          // 用了哪份简历（可选）
jdContent   String?                       // 岗位描述（可选）
mode        String                        // 面试模式：technical / behavioral 等
difficulty  String                        // 难度：easy / medium / hard
status      String  @default("preparing") // preparing → in_progress → completed
duration    Int?                          // 持续时长（秒）
score       Int?                          // 最终得分
createdAt   DateTime @default(now())
updatedAt   DateTime @updatedAt
completedAt DateTime?                     // 完成时间

关系：
  user   → User（属于一个用户）
  resume → Resume?（属于一份简历，可选）
  messages → Message[]（有多条消息）
```

### Message（一条对话消息）

```
id         String  @id @default(cuid())
sessionId  String                        // 属于哪场面试（外键）
role       String                        // user / ai
content    String                        // 消息内容
type       String                        // question / answer / feedback / system
phase      String?                       // intro / resume / tech / closing
score      Int?                          // 这条回答的得分
evaluation String?                       // AI 对这条回答的评价
createdAt  DateTime @default(now())

关系：
  session → InterviewSession（属于一场面试）
```

**关键：一对多关系，外键永远放在"多"的那张表里（Message.sessionId）。**

## 五、代码实现（三层架构）

### 5.1 Repository 层（采购员）— interview.repository.ts

7 个操作：

| 函数 | 说明 | Prisma API |
|------|------|-----------|
| `createSession(data)` | 创建一场面试 | `prisma.interviewSession.create` |
| `findSessionsByUserId(userId)` | 某人的全部面试 | `findMany` + 不返回消息 |
| `findSessionById(id)` | 一场面试详情 | `findUnique` + `include: { messages }` |
| `updateSession(id, data)` | 更新面试（改状态等） | `prisma.interviewSession.update` |
| `deleteSession(id)` | 删除面试 + 连带删消息 | `message.deleteMany` → `interviewSession.delete` |
| `createMessage(data)` | 追加一条消息 | `prisma.message.create` |
| `findMessagesBySessionId(sessionId)` | 一场的全部消息 | `findMany` + orderBy createdAt asc |

**注意：SQLite 不支持 Prisma 级联删除，所以删 Session 前要手动 deleteMany 消息。**

### 5.2 Service 层（厨师）— interview.service.ts

6 个操作，每条都有权限检查（`只能操作自己的面试`）：

| 函数 | 业务规则 |
|------|---------|
| `startInterview` | mode/difficulty 必填 |
| `getInterviews` | 直接传 userId 调 Repository |
| `getInterviewById` | session.userId 必须等于当前 userId，否则抛 404 |
| `completeInterview` | 先做权限检查 → status=completed + completedAt=new Date() |
| `deleteInterview` | 先做权限检查 → 真删除 |
| `appendMessage` | 必须是自己的，且状态不能是 completed |

### 5.3 Controller 层（服务员）

| 路由 | 方法 | 功能 |
|------|------|------|
| `/api/interview/start` | POST | 创建一场面试 |
| `/api/interviews` | GET | 当前用户的面试列表 |
| `/api/interview/:id` | GET | 面试详情（含消息） |
| `/api/interview/:id` | PATCH | 完成面试（status→completed） |
| `/api/interview/:id` | DELETE | 删除面试 |

Controller 三步骨架每次都一样：
```
① 解析请求 → getUserId(request) + 解析 params/body
② 调 Service  → 把 userId + 参数传进去（权限在 Service 里判断）
③ 返回响应  → BusinessError=400/404，其他=500
```

## 八、额外收获：AI 省钱方案（2026-08-21 补充）

### 背景

DeepSeek 用起来有点贵，项目要跑面试对话，一轮就是几块钱，学习阶段扛不住。

### 关键发现

当前项目的 AI 调用是 **OpenAI SDK 通用格式**，从 `src/lib/constants.ts` 读环境变量：
```ts
const client = new OpenAI({
  baseURL: DEEPSEEK_BASE_URL,   // process.env.DEEPSEEK_BASE_URL
  apiKey: DEEPSEEK_API_KEY,     // process.env.DEEPSEEK_API_KEY
  timeout: 30000,
  maxRetries: 2,
});

model: DEEPSEEK_MODEL          // process.env.DEEPSEEK_MODEL
```

这意味着**换平台不用改代码，只改 3 个环境变量就行！**

### 方案 ①（最推荐）：SiliconFlow

官网：https://siliconflow.cn/ （国内 AI 聚合平台，兼容 OpenAI SDK 格式）

**价格对比（约 DeepSeek 官网的 1/4）：**

| 模型 | DeepSeek 官网 | SiliconFlow |
|------|-------------|-------------|
| DeepSeek V3 输入 | ¥2/百万 | ¥0.5/百万 |
| DeepSeek V3 输出 | ¥8/百万 | ¥2/百万 |
| Qwen2.5-7B（阿里） | — | **免费额度** |

**操作（0 代码改动）：**
1. 注册 SiliconFlow 拿 API Key（sk- 开头）
2. 项目根目录新建 `.env.local`（Next.js 会自动读取，别提交 git）：

```env
# .env.local
DEEPSEEK_API_KEY="sk-xxxxxxxxxxxxxxxxxxxx"
DEEPSEEK_BASE_URL="https://api.siliconflow.cn/v1"

# 完全免费（阿里 Qwen，中文质量很好）：
DEEPSEEK_MODEL="Qwen/Qwen2.5-7B-Instruct"

# 想用 DeepSeek 但更便宜：
# DEEPSEEK_MODEL="deepseek-ai/DeepSeek-V3"
```

### 方案 ②（学习阶段强烈建议）：Mock AI 模式

**学 Day 5/6 数据库三层架构时，根本不需要真实 AI 回复**，可以写一个「假 AI 模式」：

```
MOCK_AI=true 时，不走大模型：
  - 用户说什么都返回预设好的面试题（循环出题）
  - 比如：
      第 1 轮："请做一个 1 分钟的自我介绍"
      第 2 轮："说说你最有挑战的项目经历"
      第 3 轮："你对 React Hooks 的理解是什么？"
      ...
  - 评分用随机数 6~9 分
  - 数据库照样正常：createSession → createMessage（每轮2条）→ completeInterview
```

**好处巨大：**
- 学数据库流程不花一分钱，想跑 100 次都行
- 不用担心网络问题、Token 限流
- 等 UI、Controller、Service、Repository 全部调通了，再切回真实 AI

### 方案 ③：HuggingFace 免费额度

项目已经装了 `@huggingface/inference`（package.json 第 14 行），HuggingFace 有免费推理额度：
- 模型：`Qwen/Qwen2.5-7B-Instruct`、`microsoft/Phi-3-mini` 等
- 需要拿 HF Token：https://huggingface.co/settings/tokens

缺点：免费额度有限，高峰时排队慢。不如方案 ① 直接换 env。

### 方案 ④：Ollama 本地模型（完全离线）

电脑够强（M 系列芯片 / 16GB+ 内存）可以本地跑：
- 官网：https://ollama.com/
- 下载后 `ollama run qwen2.5:7b` 就能本地跑模型
- 本地 Ollama 默认也兼容 OpenAI SDK 格式：`baseURL = "http://localhost:11434/v1"`，apiKey 随便填 `ollama` 就行
- **一分钱不花，数据完全不出本机**
