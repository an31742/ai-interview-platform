## 一、今天最大的收获：三层架构终于搞懂了

### 餐厅比喻完整版

```
用户（前端）来吃饭
    ↓
服务员（Controller）：接单、端菜、收钱
    ↓ 喊一声
厨师（Service）：检查食材新鲜不、决定怎么做、调味
    ↓ 喊一声
采购员（Repository）：去仓库拿食材/放回去
```

### 对应到代码

```
Controller（服务员）：
  ✅ 接 HTTP 请求
  ✅ 调 Service
  ✅ 返回 HTTP 响应
  ❌ 不处理业务逻辑
  ❌ 不查数据库

Service（厨师）：
  ✅ 检查业务规则（密码够长？邮箱重复？）
  ✅ 处理数据（哈希密码、生成 Token）
  ✅ 调 Repository（帮我查一下、帮我创建）
  ❌ 不处理 HTTP 请求
  ❌ 直接查数据库

Repository（采购员）：
  ✅ 查数据库（findByEmail、findById）
  ✅ 写数据库（create）
  ❌ 不做业务判断（密码对不对不归我管）
```

### 之前 vs 之后

```
之前（一个文件干所有）：
  register/route.ts 自己干了：
    ✓ 接 HTTP
    ✓ 校验参数
    ✓ 查邮箱重复
    ✓ 哈希密码
    ✓ 存 JSON 文件
    ✓ 签发 Token
    ✓ 返回响应

之后（三层各司其职）：
  Controller： 接请求 → 调 Service → 返回响应
  Service：    校验 → 调 Repository → 处理数据
  Repository： 查数据库 → 写数据库
```

### 我自己的总结（老师说完全正确）

```
Controller  → 只调用，交给 Service
Service     → 处理逻辑，交给 Repository
Repository  → 处理数据（查/写数据库）
```
