# 《高级前端 + AI 应用工程师 84 天训练手册（996版）》

> **这不是学习计划，这是一本作战手册。**
>
> 每天打开当天那一页，不需要思考今天学什么，只需要执行。

---

## 使用方式

```
🚇 地铁 30 分钟  →  理解概念（只看不写）
🌙 晚上 40 分钟  →  动手开发（Claude + 编码）
📝 睡前 10 分钟  →  记录总结 + 面试模拟
☀️ 周日 2 小时   →  集成 + 重构 + 文档
```

**自律不是每天做重大决定，而是每天执行既定流程。**

## 每日节奏说明

### 🚇 地铁 30 分钟

> **规则：** 只看不写。不打开代码。不打开 IDE。

这是最容易被忽视但最重要的环节。30 分钟专注理解：
- 通过 ChatGPT/Claude 深入一个核心概念
- 目标是理解"为什么"，不是"怎么用"
- 在手机备忘录写下 3 个关键洞察

**为什么必须在地铁？** 因为回到家你永远会被琐事干扰。通勤是你唯一不受打扰的深度思考时间。

### 🌙 晚上 40 分钟

> **规则：** 打开 Claude Code，根据当天 Prompt 执行。40 分钟必须结束。

这是一个 996 开发者能挤出的最大块时间。不要贪多：
- 20 分钟：让 AI 生成框架代码
- 20 分钟：理解、修改、提交
- **完成一个 Commit = 当天胜利**

### 📝 睡前 10 分钟

> **规则：** 不 coding，只写 docs。

写 docs 不是为了别人，是为了**帮你固化理解**。每天回答三个问题：
1. 今天我理解了什么本质？
2. 这个知识和我项目的关系是什么？
3. 如果面试官问这个，我怎么回答？

### ☀️ 周日 2 小时

> **规则：** 不开发新功能，只做 Tech Lead 做的事情。

- Code Review 本周代码
- 重构不合理的设计
- 更新 README 和架构文档
- 模拟面试官追问

## 验收标准

**每天完成的标准只有一个：**

> **今天项目比昨天前进了一行可上线的代码，或理解深了一层本质。**

不是：
- ❌ "今天看了 3 小时文档"
- ❌ "今天配置了环境"
- ❌ "今天试了一下"

而是：
- ✅ "User 模型建好了，第一次 Migration 成功"
- ✅ "Repository 层重构完成，API 路由通过了"
- ✅ "我理解了为什么 PostgreSQL 适合这个项目，写进了 docs"

## 一个请求

**不要跳 Day。**

不要觉得"这个我会了"就跳到后面。

这个手册的设计是**每一行代码、每一个概念都是下一个任务的前置依赖**。跳过一天，后面就会卡住。

如果你真的觉得某天太简单：
- 用那天的时间把代码重构得更优雅
- 用那天的时间把 docs 写得更深入
- 用那天的时间模拟面试官问你更深的问题

**但不要跳过。**

如果你发现某周对你来说太难（比如 Week 1 你还没有后端基础）：
- 看该周的目录下有没有 `小白版-*` 文件
- 小白版按你的节奏重新排了顺序，加了概念讲解
- 内容一样，只是步子更小、更慢
- 走完小白版再回头看原版，你会发现都能理解了
